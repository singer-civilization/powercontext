ResearchVault

把散落的 Markdown/TXT 笔记与论文摘录导入嵌入式 seekdb，检索结果自带出处（文件 + 行号）的速查工具。

痛点 核心功能 架构 快速开始

解决的痛点

复习和读文献时最浪费时间的不是「读」，是「找」。

1

上学期的笔记找不到了

只记得「大概在某个 .md 里提过」，目录一层层点开、编辑器全局搜索来回换，就是定位不到那段话。

2

翻几十篇论文摘录找一句话

摘录散落在几十个文件里，肉眼 grep 慢且没有排序；引文要回到原文核对，却连行号都不知道。

3

工具链太重、数据还要上云

Notion/Obsidian 插件链、向量库、云端索引对「查一句话」来说都过头了。ResearchVault 只有标准库 + 嵌入式 seekdb，数据全在本地 .vault/。

核心功能

三个命令覆盖「入库 → 检索 → 盘点」，统一入口 python -m researchvault。

① add：递归导入，重复不重复计数

目录里的 .md/.txt 按行窗口切块入库，记录相对路径、起始行号与校验和；内容没变的文件直接跳过。

$ python -m researchvault add samples
+ samples/数据库索引笔记.md（1 块）
+ samples/机器学习复习提纲.md（1 块）
+ samples/论文摘录_Attention_Is_All_You_Need.md（1 块）
导入 3 个文件，跳过 0 个未变化文件

② search：带出处的关键词打分检索

中英混合分词 + CJK 二元组召回，按分数降序输出「文件:行号 + 摘录」，行号可直接回到原文。

$ python -m researchvault search "覆盖索引"
samples/数据库索引笔记.md:13  [5.0]  - 覆盖索引：如果查询列全部包含在二级索引里，
就不用回表。`EXPLAIN` 里显示 `Using index`。

③ stats：库存概览 / JSON 输出

文档数、块数、最近导入时间一眼看清；所有命令支持 --json，方便接脚本。

$ python -m researchvault stats
文档数: 3
块数:   3
最近导入: 2026-10-31 17:13:40

架构说明

没有服务进程：每条命令打开嵌入式 seekdb → 建表 → 执行 → 关闭。

笔记 / 论文摘录 .md / .txt
本地目录
→
CLI add / search / stats
argparse 标准库
→
切块器 行窗口 ≤40 行
记住起始行号
→
嵌入式 seekdb rv_documents
rv_chunks @ ./.vault/
→
打分排序 · 输出 LIKE 召回 +
Python 侧计分

检索链路：查询 → 分词（ASCII 词 + CJK 词组/二元组）→ LIKE '%token%' 从 rv_chunks 召回 → 出现次数求和 + 整串命中加成 → 按 (-分数, 文件, 行号) 排序输出。

快速开始

要求 Python ≥ 3.11，三条命令跑通全流程：

  1. python3 -m venv .venv && source .venv/bin/activate && pip install -e '.[dev]'
  2. python -m researchvault add samples/
  3. python -m researchvault search "多头注意力"
$ python -m researchvault search "多头注意力" --limit 3
samples/论文摘录_Attention_Is_All_You_Need.md:16  [5.0]  - 多头注意力让模型同时关注不同位置、不同表示子空间的信息。
