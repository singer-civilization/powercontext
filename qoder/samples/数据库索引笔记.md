# 数据库索引笔记（复习用）

## B+ 树索引为什么适合磁盘

- B+ 树只有叶子节点存数据，非叶子节点只存键，扇出大、树高低。
- 叶子节点之间有双向链表指针，范围扫描（`WHERE id BETWEEN 10 AND 20`）非常高效。
- 对比哈希索引：哈希只支持等值查询，不支持范围查询和最左前缀匹配。

## 聚簇索引 vs 二级索引

- 聚簇索引（InnoDB 主键）叶子节点存整行数据；二级索引叶子存主键值。
- 通过二级索引查到主键后再回表取整行，叫回表（table lookup）。
- 覆盖索引：如果查询列全部包含在二级索引里，就不用回表。`EXPLAIN` 里显示 `Using index`。

## 索引失效的常见场景

1. 对索引列做函数运算：`WHERE YEAR(created_at) = 2024`。
2. 隐式类型转换：字符串列用数字比较。
3. 前导模糊匹配：`LIKE '%key'` 无法走 B+ 树。
4. 违反最左前缀：联合索引 `(a, b, c)`，只按 `b` 过滤用不上。

## 全文索引与倒排索引

- MySQL `FULLTEXT` 索引、Elasticsearch 都基于倒排索引（inverted index）。
- 倒排索引：词项 → 文档列表，适合关键词检索场景。
